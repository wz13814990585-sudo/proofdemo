# 历史记录 — Stage 13：基于证据的视频润色

## 目标

在不改变执行和验证事实的前提下，将已验证浏览器录制转化为更易观看的产品演示：围绕实际交互目标平滑缩放、显示经过插值的光标、基于已验证场景生成字幕与提示标注，并在场景边界加入克制的转场。用户最终播放的应是润色视频，同时保留原始录制、基础合成和可复核的编辑计划。

## 必须实现的结果

1. 执行时可选、非阻塞地捕获点击/填充目标的视口坐标；只记归一化数值和关联的场景/操作 ID，不记录输入值、页面文本或凭据。定位失败不得改变验证结果。
2. 从 `PASSED` 的执行报告、完整性清单、时间线和关联轨迹确定性生成有版本的润色计划。自动缩放和光标关键帧只使用真实捕获的坐标；无坐标时明确退化为静态画面，不虚构目标。
3. 字幕和标注只来源于已验证场景与断言，不能将规划器预期叙述当作已发生事实。字幕有可读对比度和入/出场；提示标注仅在对应场景验证后出现。场景边界有短时转场，不改变片段顺序或覆盖率。
4. 使用经过验证的源视频生成独立 `polished_demo.mp4`；保留基础 `demo.mp4`、版本化编辑计划和字幕源文件，并将新产物纳入哈希清单。失败时不把基础视频伪装成润色成功，也不破坏已验证的源证据。
5. 工作台明确显示润色进度和最终产物类型。视频接口只在任务成功且清单重新验证时提供润色版；CLI/旧任务继续保留基础合成语义。
6. 通过真实 Chromium/FFmpeg 产品流程与媒体探测/帧级检查证明缩放、光标、字幕/标注和转场确实出现在输出中；覆盖无坐标退化、恶意文本转义、视频/时间线篡改、渲染失败和重启恢复。运行完整测试、Ruff、mypy、schema 漂移检查和前端构建。

# 历史记录 — Stage 12：有证据约束的自主探索

## 目标

让用户只给出一个获授权的陌生产品 URL 和演示目标时，ProofDemo 能在明确预算内主动观察站点页面与可操作控件，将真实页面证据交给规划器，并且只执行经证据锚定、通过现有安全门禁的 DemoSpec。Stage 11 已提供产品工作台，但原规划器仅凭 URL 和文字猜测界面；本阶段要消除这一关键缺口，同时如实暴露不支持的动态流程。

## 必须实现的结果

1. 新增隔离的同源探索浏览器：读取页面标题、结构、可见链接、按钮与表单标签，在有界页面/控件/时间预算内自主选择要继续观察的页面；不提交表单、不执行有状态点击、不注入凭据，也不访问跨源导航。
2. 将每页 URL、实际观察到的控件、导航来源与有限截图记录为有版本的 ExplorationReport；不采集输入值或隐藏凭据，观察失败与预算耗尽必须明确标为 `BLOCKED` 或 `PARTIAL`，不能伪装成完整产品理解。
3. 模型只能建议从已观察的候选链接中选择下一页，或从探索报告提出 DemoSpec；应用层重新验证所有建议，不允许模型直接操作浏览器或声明执行成功。
4. 每个待执行的导航和目标必须与已观察页面及控件建立可检查的关联；无法锚定的规划候选在执行前停止，带着具体缺口交给 UI，而不是让浏览器盲试。对点击后才出现、未在只读探索中观察到的动态控件应明确报告为当前能力边界。
5. Stage 11 的任务生命周期增加探索状态与实时观察事件；UI 能查看探索页面、控件、候选规范的证据覆盖和被阻塞原因。原有 SafetyService、ExecutionService、验证与视频门禁保持权威。
6. 至少通过两个结构不同的本地 Web fixture 证明从 URL/目标到有证据锚定的计划和最终视频；测试覆盖跨源链接、重定向、风险导航、预算耗尽、模型伪造控件、无模型/无浏览器与中断恢复。运行完整测试、Ruff、mypy、schema 检查和前端构建。

## 不在范围内

- 探索阶段的任意状态变更、登录、凭据注入和自动购买；
- 对任何陌生网站都能成功的泛化质量声明；
- 自动缩放、字幕、标注、转场及托管 SaaS（后续阶段）。

# 历史记录 — Stage 11：ProofDemo 产品工作台

## 目标

让本地用户在前端输入产品 URL 与一句演示目标，启动经过验证的演示，实时看到规划、浏览器执行和渲染进度，并在同一界面查看 DemoSpec、场景、断言证据和最终视频。Stage 10 完成的是 Engine V1，不等于 Product V1。

## 必须实现的结果

1. API 接收 URL、目标、受众、语言和目标时长，创建有稳定 ID 的本地任务；规划、执行、验证、采集和渲染复用现有服务，而不是另建一条弱化验证的路径。
2. 任务状态明确区分排队、规划、等待批准、执行、渲染、通过、失败和阻塞；进程重启后不能把中断任务伪装成成功。
3. 任务状态、进度事件、候选 DemoSpec 和运行产物在受限目录中持久化；同时执行的任务有明确上限。
4. 浏览器操作与验证结果可实时订阅。实时预览只提供本地、有界的浏览器截图；不得在事件或日志中传输填充值或凭据，并须说明页面本身可能显示敏感内容。
5. 风险操作仍须单独、明确批准；类似凭据的填充始终被阻止。未配置模型、浏览器或媒体工具时，界面显示可操作的 BLOCKED 原因。
6. UI 提供实际输入与 Generate 操作，展示状态、场景、DemoSpec、验证结果、产物完整性和可播放/下载的视频；失败、阻塞和未经验证的运行不显示成功视频。
7. API、UI 和真实本地 Todo 工作流的测试覆盖关键生命周期、安全门禁和错误路径；运行全部后端测试、Ruff、mypy、schema 检查和前端构建。
